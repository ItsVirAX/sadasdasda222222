# PS Archive Manager (Tauri)

برنامه ویندوزی برای فهرست‌کردن آرشیو PS4/PS5. بررسی آنلاین (اسم بازی و آخرین نسخه آپدیت) با یک پنجره مرورگر واقعی (WebView2) انجام می‌شود. برنامه هیچ فایل اصلی را حذف، کپی یا جابه‌جا نمی‌کند. برای فایل‌های شناسایی‌شده می‌تواند پوشه بازی و شورتکات ویندوزی بسازد.

## ساخت فایل نصب با GitHub Actions (یک‌بار)
1. در github.com یک مخزن (repository) جدید بسازید (خصوصی هم مشکلی ندارد).
2. همه فایل‌های این پوشه را، **از جمله پوشه `.github`**، در مخزن آپلود کنید (با Git یا «Add file → Upload files»).
3. تب **Actions** → «Build Windows app» → **Run workflow**.
4. بعد از حدود ۱۰ دقیقه، همان صفحه را باز کنید و در بخش **Artifacts** فایل `PS-Archive-Manager-windows` را دانلود کنید. داخلش فایل نصب (`...setup.exe`) است. نصب روی ویندوز نیاز به دسترسی ادمین ندارد.

## استفاده
- «انتخاب پوشه آرشیو» → پوشه را از پنجره انتخاب پوشه ویندوز انتخاب کنید؛ سپس فایل‌های پشتیبانی‌شده اسکن می‌شوند.
- اگر گزینه ساخت شورتکات فعال باشد، برای هر فایل دارای نام بازی یک میانبر `.lnk` در مسیر `PS Archive Shortcuts\نام بازی` ساخته می‌شود. میانبر به فایل اصلی اشاره می‌کند؛ فایل اصلی سر جای خودش می‌ماند.
- برای حذف فایل اصلی از ویندوز، روی شورتکات راست‌کلیک کنید و «Open file location» را بزنید؛ حذف خود شورتکات فقط لینک را حذف می‌کند، نه فایل اصلی.
- بررسی آنلاین خودکار بعد از اسکن شروع می‌شود.
- اگر سایت «تأیید انسانی» (Cloudflare) خواست، یک پنجره باز می‌شود؛ یک‌بار انجامش دهید و پنجره خودش بسته می‌شود.
- اگر بررسی آنلاین ۳ بار پشت‌سرهم ناموفق شد، پایین صفحه «گزارش عیب‌یابی» پر می‌شود؛ آن را برای توسعه‌دهنده بفرستید.

- تنظیم «Provider» دیگر خودکار تغییر/ذخیره نمی‌شود؛ جابه‌جایی فقط برای همان اجرا است.
- حلقه با «سهمیه/کلید همه سرویس‌ها تمام شد» یا ۳ خطای پشت‌سرهم متوقف می‌شود و پنجره تنظیمات فقط یک‌بار باز می‌شود.
- پنجره تنظیمات فقط وقتی خودکار باز می‌شود که حالت Serper یا Google انتخاب شده و کلیدش ناقص است.
- شورتکات فقط برای اسم‌های قابل‌اعتماد ساخته می‌شود (از سایت، ویرایش دستی، یا ردیف تأییدشده).
- Rust: حذف پیشوند `\\?\` ویندوز از مسیرها (برای .lnk و explorer)، فایل `.psa-index.json` برای جلوگیری از برخورد شورتکات‌های هم‌نام، رعایت محدودیت ۲۶۰ کاراکتری مسیر، و اسکن پوشه خارج از ترد async.

## تغییرات نسخه 1.5.0
- سایت‌های ORBISPatches/PROSPEROPatches لیست آپدیت را بعد از لود صفحه با XHR (`/api/internal/loadpatches`) می‌گیرند، پس selectorهای قدیمی (`data-version`) در HTML اولیه وجود ندارند. حالا اسکریپت داخل پنجره بررسی، پاسخ همان درخواست را (فقط‌خواندنی) می‌خواند و نسخه‌ها را از کلیدهای مشخص `version`/`app_ver` درمی‌آورد.
- اسم بازی از `h3.h3-title`، `h1`، `og:title` یا عنوان صفحه (با حذف نام سایت و Title ID) برداشته می‌شود؛ صفحه‌های «404/Not found/Just a moment» به‌عنوان اسم پذیرفته نمی‌شوند.
- دکمه «تست یک Title ID»: بدون اسکن، یک Title ID را با پنجره‌ی قابل‌مشاهده تست می‌کند و نتیجه‌ی کامل را در «گزارش عیب‌یابی» نشان می‌دهد؛ دکمه «کپی گزارش» هم اضافه شد.
- پیام خطا دقیق شد: شکست بررسی از سایت دیگر به‌عنوان «تمام شدن سهمیه/کلید» گزارش نمی‌شود و پنجره تنظیمات برایش باز نمی‌شود.
- اگر اسکریپت صفحه اصلاً پیامی برنگرداند، گزارش timeout مشخص می‌کند `script_ran=true/false`.

## تغییرات نسخه 1.6.0
- **نام پوشه شورتکات‌ها = «اسم بازی + ریجن»** (مثلاً `FC 27 EU` و `FC 27 US`). داخل هر پوشه فقط شورتکات `.lnk` به مسیر اصلی هر فایل ساخته می‌شود؛ هیچ فایلی کپی یا جابه‌جا نمی‌شود. اگر ریجن مشخص نباشد، فقط اسم بازی استفاده می‌شود. پوشه‌های قدیمی (بدون ریجن) خودکار حذف نمی‌شوند.
- **سرعت بررسی آنلاین:** چند پنجره‌ی بررسی هم‌زمان (پیش‌فرض ۳، قابل تغییر از ۱ تا ۶ کنار دکمه شروع) و پنجره‌ها به‌صورت پیش‌فرض پنهان‌اند، پس صفحه‌ی سفید و باز/بسته شدن دیده نمی‌شود. فقط اگر سایت تأیید انسانی بخواهد پنجره نشان داده می‌شود. ذخیره و رندر جدول هم هر حدود ۱ ثانیه یک‌بار انجام می‌شود، نه بعد از هر بازی.
- اصلاح پاک‌سازی اسم: دیگر کلمه‌هایی مثل Home/Patches از وسط اسم بازی حذف نمی‌شوند (مثلاً «Homefront» درست می‌ماند).

## تغییرات نسخه 1.6.1
- خطای ساخت شورتکات حالا متن واقعی خطا را نشان می‌دهد (در نوار وضعیت و در «گزارش عیب‌یابی»)، نه فقط تعداد.
- نتایج بررسی آنلاین در حافظه‌ی همین برنامه (localStorage) کش می‌شوند و Title IDهایی که قبلاً موفق بوده‌اند دوباره از سایت پرسیده نمی‌شوند. اگر ماوس را روی اسم بازی نگه دارید، منبع (سایت/ویرایش دستی) و زمان ذخیره نشان داده می‌شود.
- دکمه «پاک کردن کش بررسی آنلاین»: همه‌ی Title IDها دفعه بعد دوباره از سایت بررسی می‌شوند؛ اسم‌های دستی و تأییدها حفظ می‌شوند.

## تغییرات نسخه 1.6.2
- **رفع باگ ساخت شورتکات (خطای «path too long»):** اسکریپت PowerShell لیست JSON را با `$json | ConvertFrom-Json` می‌خواند؛ در Windows PowerShell 5.1 این کار وقتی لیست بیش از یک آیتم دارد، کل لیست را به‌عنوان «یک آیتم» به حلقه می‌دهد، مسیرهای همه فایل‌ها به هم می‌چسبند و از ۲۶۰ کاراکتر رد می‌شود. نتیجه: هیچ شورتکاتی ساخته نمی‌شد. حالا لیست داخل یک شیء (`{"items":[...]}`) فرستاده می‌شود و با `ConvertFrom-Json -InputObject` خوانده می‌شود.
- شورتکات‌ها در دسته‌های ۲۰۰تایی ساخته می‌شوند (حد ۲ مگابایتی ConvertFrom-Json در PowerShell 5.1 برای آرشیوهای بزرگ) و اگر یک دسته خطا بدهد، بقیه ادامه پیدا می‌کنند.

## تغییرات نسخه 1.6.3
- رفع خطای «Parameter set cannot be resolved using the specified named parameters» در ساخت شورتکات: در Windows PowerShell 5.1 ترکیب `Split-Path -LiteralPath ... -Parent` خطا می‌دهد و برای هر فایل تکرار می‌شد. به‌جایش از `[System.IO.Path]::GetDirectoryName` استفاده می‌شود.

## تغییرات نسخه 1.6.4
- **نام پوشه/شورتکات فقط ASCII:** WScript.Shell فقط مسیرهایی را ذخیره می‌کند که همه‌ی حروفشان در code page سیستم باشد؛ مثلاً «METAL GEAR SOLID Δ» به «?» تبدیل می‌شد و ساخت شورتکات شکست می‌خورد. حالا حروف خاص تبدیل می‌شوند (Δ ← Delta، é ← e، ™ حذف، …) و حروف ناشناخته `_` می‌شوند. اسم پوشه‌ی بازی‌های قبلی که با حرف خاص ساخته شده بودند ممکن است خالی بماند؛ دستی پاکش کنید.
- **بدون پنجره‌ی PowerShell:** اسکریپت ساخت شورتکات با پرچم CREATE_NO_WINDOW در پس‌زمینه اجرا می‌شود و دیگر پنجره‌ای باز و بسته نمی‌شود.

## تغییرات نسخه 1.7.0 — بررسی آپدیت‌ها (نیمه‌ی آفلاین)
- تب جدید **«بازی‌ها و آپدیت‌ها»**: هر بازی یک ردیف (اسم، ریجن، پلتفرم، بازی اصلی، لیست آپدیت‌های آرشیو، DLC، آخرین نسخه‌ی آنلاین اگر معلوم باشد، وضعیت، یادداشت، لینک سایت). فیلتر وضعیت، جستجو، مرتب‌سازی و دکمه‌ی «گزارش آپدیت (CSV)».
- فایل‌های چندپارتی (`_0 … _N` و `.partNN.rar`) یک «بسته» حساب می‌شوند. پارت‌های بدون هدر نوع را از بسته می‌گیرند، پس هشدار «نوع نامشخص» و «احتمال تکراری» برای هر پارت دیگر نمی‌آید.
- تشخیص بسته‌ی **ناقص** از روی شماره‌ی پارت‌ها (مثلاً پارت ۵ موجود نیست؛ یا فقط `_12` از یک آپدیت هست).
- نسخه از `A####` (نسخه‌ی برنامه)، `V####` (نسخه‌ی محتوا)، `v1.014.001` و `[01.685.672]` خوانده می‌شود؛ `-DP` یعنی آپدیت **دلتا** و جدا حساب می‌شود.
- وضعیت‌ها: آپدیت/DLC بدون بازی اصلی، بازی اصلی ناقص، آپدیت ناقص، نوع نامشخص، فقط دلتا، آپدیت جدیدتر موجود است، به‌روز، آپدیت دارد (آنلاین بررسی نشده)، فقط بازی اصلی. آپدیت‌های قدیمی‌تر و نسخه‌های تکراری در یادداشت می‌آیند؛ برنامه هیچ فایلی را حذف نمی‌کند.
- اگر نوع یک بسته در هیچ فایلی (هدر/نام) مشخص نباشد، از A-tag/DP یا برچسب محتوا حدس زده می‌شود و در یادداشت «حدس زده شد» نوشته می‌شود.

## تغییرات نسخه 1.7.1 — نسخه‌ها هیچ‌وقت از کش کهنه تفسیر نمی‌شوند
- **اسم بازی کش می‌شود (عوض نمی‌شود)، نسخه‌ها نه:** برای هر Title ID زمان آخرین خواندن نسخه‌ها (`verAt`) ذخیره می‌شود.
- حکم «**به‌روز**» فقط وقتی داده می‌شود که نسخه‌ها در ۱۲ ساعت گذشته از سایت خوانده شده باشند (ثابت `FRESH_MS` بالای کد). در غیر این صورت وضعیت «نسخه‌ی آنلاین قدیمی است؛ دوباره بررسی کنید» می‌آید. (حکم «آپدیت جدیدتر موجود است» از داده‌ی قدیمی هم معتبر می‌ماند، چون نسخه‌ها فقط بالا می‌روند.)
- ستون «آخرین نسخه آنلاین» سن داده را نشان می‌دهد (✓ ۳ ساعت پیش / قدیمی: ۲ روز پیش) و در CSV ستون `online_checked_at` اضافه شد.
- دکمه‌ی **«بررسی تازه‌ی نسخه‌ها از سایت»** (تب بازی‌ها): همیشه از سایت می‌خواند، روی بازی‌های نمایش‌داده‌شده (با فیلتر می‌توانید فقط «قدیمی» ها را بدهید). اگر سایت پاسخ نداد یا نسخه‌ای نخواند، داده‌ی قبلی پاک نمی‌شود و خطا علامت می‌خورد.
- تیک «بعد از اسکن نسخه‌ها را هم تازه کن» (پیش‌فرض خاموش).

## تغییرات نسخه 1.7.2 — عیب‌یابی نسخه‌های سایت
- گزارش واقعی نشان داد صفحه‌ی سایت هیچ درخواست شبکه‌ای (`requests=[]`) در پنجره‌ی بررسی نمی‌فرستد یا ما نمی‌بینیم؛ پس نسخه‌ها خالی می‌ماند. این نسخه اسکریپت صفحه را برای کشف علت کامل‌تر می‌کند:
  - همه‌ی درخواست‌های fetch/XHR با **متد، آدرس، وضعیت، اندازه‌ی پاسخ و ابتدای بدنه‌ی درخواست** ضبط می‌شوند، همچنین لیست `performance` مرورگر، iframeها، scriptها، متن صفحه و بخش‌هایی از HTML اطراف کلمه‌های patch/version.
  - اگر ۳ ثانیه بعد هیچ درخواستی نیامد، یک بار صفحه اسکرول می‌شود (بعضی سایت‌ها لیست را با اسکرول لود می‌کنند).
  - دکمه‌ی «تست یک Title ID» حالا حالت تشخیصی دارد: تا ۲۵ ثانیه صبر می‌کند و گزارش کامل می‌دهد.
  - اگر بررسی عادی اسم را پیدا کند ولی نسخه‌ای نخواند، گزارش کامل در «گزارش عیب‌یابی» ذخیره می‌شود و در تب بازی‌ها یادداشت «سایت لیست نسخه‌ها را برنگرداند/خوانده نشد» می‌آید.

## تغییرات نسخه 1.8.0 — خواندن سریع نسخه‌ها از سایت
- گزارش واقعی نشان داد صفحه‌ی سایت لیست نسخه‌ها را با `POST /api/internal/loadpatches` و بدنه‌ی `{"titleid":…,"key":…}` می‌گیرد، حدود **۲۰ ثانیه** بعد از لود صفحه (اول اسکریپت‌های تبلیغات و رضایت‌نامه). برنامه ۱۲ ثانیه صبر می‌کرد و نسخه‌ها خالی می‌ماند.
- حالا اسکریپت داخل پنجره، همان لحظه‌ی شروع، HTML صفحه‌ی همان بازی را می‌خواند، کلید ۶۴ حرفی هر بازی را پیدا می‌کند و همان درخواست را خودش می‌فرستد؛ اسم بازی هم از همان HTML گرفته می‌شود. به‌جای ~۲۵ ثانیه، هر بازی چند ثانیه (عمدتاً ساخت پنجره) طول می‌کشد.
- اگر کلید در HTML پیدا نشد، مثل قبل منتظر درخواست خود صفحه می‌ماند (حداکثر ۳۵ ثانیه) و اگر هیچ نسخه‌ای نیامد، گزارش کامل در «گزارش عیب‌یابی» می‌آید.
- کش‌هایی که قبلاً بدون نسخه ثبت شده‌اند (سایت اسم داشت ولی نسخه‌ای خوانده نشده بود) در بررسی بعدی، اگر بازی ردیف آپدیت داشته باشد، خودکار دوباره خوانده می‌شوند.

## تغییرات نسخه 1.8.1
- **رفع باگ:** تشخیص «درخواست لیست نسخه‌ها» با کلمه‌ی `patch` انجام می‌شد و آدرس‌های تبلیغاتی (مثل `gum.criteo.com/...domain=orbispatches.com`) هم آن را فعال می‌کردند؛ برنامه بعد از ~۴ ثانیه بدون نسخه تمام می‌کرد. حالا فقط درخواستی که آدرسش `loadpatches` دارد شمرده می‌شود.
- گزارش مسیر مستقیم (`direct=`) حالا زمان هر مرحله و وضعیت HTTP را دارد، و در «تست یک Title ID» اینها هم می‌آید: جای رشته‌های ۶۴ حرفی (کلید) در HTML صفحه (`hex64=`) و بخش‌هایی از `titleview.js` که می‌گوید صفحه چه زمانی و چگونه نسخه‌ها را می‌گیرد (`titleview=`).

## تغییرات نسخه 1.8.2 — اسکریپت صفحه دیگر بی‌صدا نمی‌میرد
- گزارش `status: timeout` با `script_ran=true` یعنی اسکریپت اجرا شد (`boot`) ولی هیچ نتیجه‌ی نهایی نفرستاد. ممکن بود حلقه‌ی اسکن با یک خطا بمیرد، صفحه reload شود و ساعت از اول شروع شود، یا نتیجه خیلی بزرگ شود. سه محافظ اضافه شد:
  - **حلقه‌ی اسکن** با try/catch محافظت می‌شود و خطا ثبت می‌شود (`err=…` در گزارش).
  - **Watchdog:** در هر حالت حداکثر ~۳۸ ثانیه بعد از اولین شروع جواب می‌دهد (به‌جز وقتی تأیید Cloudflare روی صفحه است) تا قبل از timeout ۵۰ ثانیه‌ای برنامه.
  - **زمان شروع و شمارنده‌ی reload** در `sessionStorage` می‌ماند (`boots=N` در گزارش)، پس reload ساعت را صفر نمی‌کند.
  - اندازه‌ی نتیجه در URL محدود شده (حداکثر ~۲۲ هزار حرف)، تا گزارش بزرگ نتیجه را از بین نبرد.

## تغییرات نسخه 1.8.3
- **مسیر مستقیم کار می‌کند** (گزارش واقعی PPSA29660: `key0@0.5s:ok(3)`، حدود نیم‌ثانیه). سایت PS5 اسم فیلد نسخه را `content_ver` گذاشته و مقدار سه‌بخشی دارد (`01.002.001`)، برای همین نسخه‌ها خالی می‌ماند. حالا کلیدهای `version`، `content_ver`، `app_ver`، `patch_ver` و مقدارهای دو تا چهار بخشی خوانده می‌شوند (فیلدهایی مثل `required_firmware: 14.22.00.00` به‌عنوان نسخه حساب نمی‌شوند).
